# First Operational Run Checklist

This checklist is for the first manual daily cycle before API automation is introduced.

## A. Set the run context
- [ ] Record run date, exact UTC timestamp and local timezone.
- [ ] Record the market regime and major scheduled events.
- [ ] Define the eligible instrument universe and minimum liquidity for each market.

## B. Discover candidates
- [ ] Scan crypto, equities, commodities/metals, FX and ETFs/indices.
- [ ] Record no more than 15 initial candidates.
- [ ] Record the exact instrument, venue, quote currency and discovery price.
- [ ] Keep social-media-only claims in the lead queue, not the validated shortlist.

## C. Validate
- [ ] Find at least three evidence classes per serious candidate.
- [ ] Include at least one primary or established source for each material catalyst.
- [ ] Check freshness, publication time, retrieval time and source independence.
- [ ] Check price structure, liquidity, spread and event calendar.
- [ ] Record counter-evidence and unresolved questions.

## D. Rank and qualify
- [ ] Score candidates using 03_SCORING_MODEL.md.
- [ ] Apply every hard gate in the scoring and risk documents.
- [ ] Deep-dive no more than three candidates.
- [ ] Do not label anything Entry Candidate without confirmation and explicit invalidation.

## E. Publish and learn
- [ ] Save the dated daily log and candidate CSV snapshot.
- [ ] Schedule 1D/3D/7D/14D/30D reviews.
- [ ] Preserve rejected candidates and rejection reasons.
- [ ] Review prior candidates without changing their original discovery records.

## First-run success criteria
The first run is successful if the process produces an auditable record, even if no trade qualifies. A zero-opportunity day is a valid result. Do not manufacture candidates to fill a quota.
